### P1-A′（高，已修）"掩码为空"与"覆盖完备"之间缺显式校验

  的频道计算"目标圆域采样点到最近无信号站点的最大距离"，写入记录

- `_finished` 收紧：`all_channels_resolved` 额外要求**全部证书 `certified`**。
- 新增 `verify_coverage_completeness()`：离线自检候选格网是否覆盖完备。

### P2-A（中）`_search_plan` 里 `remaining_sources` 的估计口径偏乐观

```python
remaining_sources = min(MAX_SOURCE_COUNT - len(self.cleared), len(self._active_channels()))
```

`len(self._active_channels())` 包含**所有未清除且未排除**的频道。但已被排除的
频道在 `_finished` 里会被判成"不存在"，所以真实剩余源数的上界应该是
`未清除频道数`，而 `len(_active_channels())` 在排除滞后时**偏大**。
影响：`_expected_finds` 被高估 → 搜索选项的"性价比"被高估 → 更倾向去搜索
而不是去追击。本次因为源多（11 个）掩盖了，源少时会放大。

**建议。** 直接用 `MAX_SOURCE_COUNT - len(self.cleared)` 与
`未清除频道数` 的较小者，并加注释说明为什么。

### P2-B（中）`_follow_up_seconds` 用全区域均值，低估后续清除代价

```python
mask = np.ones(len(self.coarse.points), dtype=bool)   # 全区域！
remaining = np.linalg.norm(self.coarse.points[mask] - waypoint, axis=1)
return float(np.mean(remaining)) / ROBOT_SPEED_MPS
```

函数名是"新发现一个目标后的后续移动时间"，但掩码是**全区域**，
与"新发现的源在哪"无关。用全场平均距离（约 1200 m → 240 s）当后续代价，
对**任何**停靠点都是同一个常数，等于没参与评分。真正应该估的是
"该停靠点的接收圆内，发现源的平均追踪距离"。

**建议。** 把掩码换成 `self._reach(waypoint)`，即只对该停靠点能覆盖到的
区域取平均。

### P2-C（中）频道切换 224 s 未被优化

224 次切换 = 224 s，占虚拟时间 4.9%。`_order_measures` 只做了
"先测当前频道、再按编号升序"，没有跨停靠点做切换规划。
例如 `(1200,0)` 那次 9 个频道按 18,7,8,10,11,12,14,15,19 顺序测，
首尾频道与上一站的衔接可以更好。

**建议。** 无需大改，在 `_order_measures` 里把"上一站结束时的频道"作为
排序第一键即可（当前只考虑 `self.current_channel`，逻辑上已接近，
但停靠点切换后没有重新优化顺序）。
