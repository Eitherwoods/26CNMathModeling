# 问题四任务图使用说明

本目录的图由 `codes.problem4_plotting` 生成，一局任务一张**四联图**（`.png` 供预览，`.svg` 供论文插入）。

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| `practice_p4_L1.{png,svg}` | **官方模拟器真实演练**（14:15，4全向+6定向共10源） | 10/10 清除、`all_channels_resolved`、虚拟 33005 s；记录 `output/Problem4/mission_p4_20260911-141541.json` |
| `mission_all_channels_resolved.{png,svg}` | 离线 `--sources 12 --seed 1 --figures` | 混合12源（6个定向），12/12清除 + 8频道证书判为不存在；记录 `output/protocol/offline-mission_p4_20260911-142326.json` |
| `mission_cleared_limit.{png,svg}` | 离线 `--sources 16 --seed 1 --directional 0 --figures` | 全向16源，清满上界收工；记录 `output/protocol/offline-mission_p4_20260911-142336.json` |

离线记录一律落在 `output/protocol/`（不是 `output/Problem4/`），在线演练记录才在 `output/Problem4/`；
约定与清单见 `output/README.md`、`output/protocol/README.md`。

真实演练那张只有轨迹、证据、收敛、时间四幅，**没有干扰源星号**（真值只在测试端）；其余读法完全相同。

重新生成：

```powershell
python -m codes.problem4_solution --sources 12 --seed 1 --figures
python -m codes.problem4_solution --sources 16 --seed 1 --directional 0 --figures
# 演练之后：从记录文件重画（没有真值，故不画干扰源与朝向）
python -m codes.problem4_plotting "output/Problem4/mission_p4_时间戳.json" --name practice_p4_L2
```

## 四幅子图怎么读

**(a) 轨迹与目标**　虚线圆＝1800 m 目标区域边界；蓝线＝机器狗实际路径；黑方块＝起点(0,0)；星号＝干扰源真值（**只有离线案例有**，红＝已清除，蓝＝未清除）；半透明扇形＋箭头＝定向源朝两侧各90度的正面接收半平面与发射法向，全向源没有扇形。
看点：轨迹应当既有在区域内部的横向绕行（为了产生方位角视差、逼近目标），又有贴着**外圈**绕一整圈的点——外圈是为了让边界朝外的定向源也能被正面看到。若某处有源却整局没靠近，说明追踪失效。

**(b) 覆盖证据完成度**　横轴＝该频道已做无信号检测的搜索顶点比例（满分为全部37个顶点）；颜色＝状态：红=已清除、灰=已证明不存在、蓝=已发现未清除、深灰=未证明、橙=模型异常；虚线＝100%。
看点：这是"结论做没做完整"的自检图。**只有灰色条到100%才是"该频道不存在"的严格证据**；红条满不满都不重要（已清除不需要覆盖）。若结束时除红/灰之外还有半截条，说明任务没做完（预算/轮数用尽），此时 `stop_reason` 必然不是完成态。

**(c) 可能位置集合收敛**　横轴＝该频道累计检测次数；纵轴（对数）＝该频道全部存活位置单元到当前位置的最远距离；红虚线＝20 m 清除半径。
看点：曲线跌破20 m 才具备"可靠清除"资格（此时可以原地清除）。曲折上升是正常的——纵轴是"到**当前**位置的最远距离"，机器人一移动就变；平台期说明该次读数没带来新信息（无信号/背面），收缩主要靠示向读数。

**(d) 动作时间构成**　一根堆叠柱，按附件2的虚拟时间口径拆成：移动 / 检测与调整天线 / 频道切换 / 光学定位与清除。
看点：问题四里**移动占约90%**（12源混合案例：移动36227 s＝90.5%、检测3142 s＝7.9%、切换579 s＝1.4%、清除60 s＝0.1%）。因为要跑完37个顶点的外圈。注意虚拟时间不是真实耗时：真实墙钟主要由本地规划计算决定，问题四约7 ms/动作，一局预计75—90 s（实测依据见 `solutions/problem4_flow.md`）。

## 能怎么用、不能怎么用

**可以用**：
- 算法自检：每改一次参数就重跑 `--figures`，对比 (b) 是否更快满覆盖、(c) 是否更快跌破20 m、(d) 的移动占比是否下降。
- 方法示意插图：把 (a) 或 (d) 作为"算法行为"示意放进论文/答辩，图注必须写明"本地桩离线案例，非官方演练成绩"。
- 讲解策略：向队友说明"为什么不沿示向线直走而要走横向视差"，(a) 比文字直观。

**不能用来**：
- 不能作为题面要求的演练结果或成绩。本地桩不复刻官方误差场、案例分布与判定细节，图上的清除数、耗时、比例都不能写进论文的结论表。
- 演练记录出的图**没有星号**（真值只在测试端），面板 (a) 只剩轨迹，读法与离线图相同但看不到"是否真的清干净"。
- 论文里的正式数据必须用模拟器导出的记录（界面"指令与反馈"/演练结果、`.jlog`、以及 `output/Problem4/mission_p4_*.json` 里由本机策略记录的部分），并以模拟器导出为准。

## 一个已知的可读性小问题

两次同 `stop_reason` 的任务会生成同名文件互相覆盖（如再次跑出 `all_channels_resolved` 就会覆盖现有那张）。需要保留多次对比时，用完 `python -m codes.problem4_plotting <记录> --name <自定义名>` 指定文件名。
