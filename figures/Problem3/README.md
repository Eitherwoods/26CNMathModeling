# 问题三图件说明

## sprint_tradeoff（速通前沿：清除率 × 平均清除时间权衡折线图）

**内容编码**

- 蓝色实线（圆点）：V3 策略（`codes.v3policy`）的"速通前沿"。把收尾条件从
  "全部未排除格点被覆盖证书锁死"替换为"已清除 K 个源即停"，K=10/12/14/16
  四档（K=16 即完整策略，因为题面上界就是 16）。横轴为平均清除时间
  （总虚拟时间 / 实际清除源数，24 种子均值），纵轴为平均清除率
  （实际清除数 / 真实源数）。
- 绿色虚线：清除率 100% 参考线；蓝色曲线右端点 K=16 = 完整覆盖证书策略
  （275.8 s/源，24/24 局满清）。
- 红色点线：题目目标 180 s/源。
- 橙色空心方块：MPC 主线（`codes.strategy_p3`）对照点——速通 K=10
  （235.0 s/源 @ 92.3%）与完整证书（315.7 s/源 @ 100%），12 种子口径。

**数据来源**

- V3 前沿四点：`codes/sprint_frontier.py` 在本地官方同构 Engine
  （`codes/local_simulator.py`，1800 m 落点口径）种子 1–24 上的确定性输出，
  原始数据 `output/localsim/bench-zc/p3-sprint-frontier.json`
  （schema `p3-sprint-frontier-v1`）。
- MPC 对照两点：`benchmark_q34_local` 12 种子（`p3-sprint-info.json` 与
  `p3-baseline-r1800.json`/`p3-adopted-24.json`）。
- 作图脚本：`codes/plot_sprint_tradeoff.py`（PNG 预览 + SVG 论文版）。

**可支持的结论**

1. 速通前沿随清除率趋近 100% 陡峭收敛：清除率 92% 时 ≈254 s/源，
   98.7% 时 ≈266 s/源，100% 时 275.8 s/源；在 100% 清除率处没有
   "既保比例又大幅省时"的廉价折中点。
2. 前沿最左端（K=10，清除率仅 81.5%，最差局 62%）也只到 232.3 s/源，
   且该数字因分母（实际清除数 < 真实源数）偏乐观——**180 s/源 位于前沿
   与目标线的左外侧，在"清除率 100%"约束下不可达**。
3. V3 完整证书策略（275.8）同时优于 MPC 的速通点（235.0，且仅 92.3%），
   说明 V3 的架构优势不是"靠放弃收尾换来的"。

**论文建议位置**

"结果分析/权衡讨论"一节，与题目两个统计量（清除比例、平均定位清除时间）
的定义张力直接对应；可配合 `solutions/problem3_flow.md` §13.5/§14.4 的
下界分析文字。

**使用限制**

- 本图为**本地官方同构 Engine 的 24 种子统计**，不是官方模拟器成绩；
  演练实测锚点见 `output/Problem3/mission_p3_20260913-031656.json`
  （12 源 255.8 s/源，100% 清除，完整证书）。
- BHH/速通等下界讨论属启发式估计，图中不呈现置信区间；种子数 24，
  单点均值波动约 ±5 s/源。
- "180 s/源目标线"是队伍内部设访目标，非题目要求，图注中需说明。
